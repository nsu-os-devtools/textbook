\chapter{Как начать работу в Linux}
\label{ch:02-linux-access}

\section{Выбор рабочей среды}

Если на вашем компьютере уже установлен Linux, откройте терминал и
выполните первые команды из раздела~\ref{sec:first-steps-terminal}.
Команды будут работать с файлами на вашем компьютере. Варианты установки
Linux на личный компьютер рассмотрены в разделе~\ref{sec:local-linux}.

Для работы на учебной виртуальной машине (ВМ) достаточно компьютера
с доступом к сети НГУ. Каждому студенту предоставляется своя ВМ с Ubuntu
и диском объёмом 20--40~ГБ. Она доступна до конца семестра.
Вы вводите команды в окне на своём компьютере, а выполняются они на ВМ.
Чтобы начать работу, к ней нужно подключиться по SSH.

\section{Подготовка к подключению}

\subsection{Доступ к сети НГУ}

Если ваш компьютер подключён к сети кампуса НГУ, можно сразу переходить
к выбору программы для подключения. Если вы дома или используете
мобильный интернет, сначала подключитесь к университетской сети через
VPN (рис.~\ref{fig:ssh-access}). Инструкцию по настройке VPN вы получите
вместе с данными для доступа. Для получения доступа обратитесь
в службу поддержки НГУ по адресу \fpath{support@nsu.ru}.

Для входа семинарист сообщит адрес сервера, имя пользователя и способ
входа (по паролю или по ключу). Вместе с ними получите
\textbf{отпечаток ключа сервера} --- строку, по которой вы проверите
сервер при первом подключении. Если семинарист указал \textbf{порт},
запишите его номер. По номеру порта сервер определяет, какой программе
передать запрос на подключение. Обычно SSH использует порт~22.

\subsection{Как открыть терминал на своём компьютере}

\begin{itemize}
  \item \textbf{Windows.} Откройте меню «Пуск», введите «PowerShell»
    и откройте Windows PowerShell. Если вы пользуетесь приложением
    «Терминал Windows», выберите в нём вкладку PowerShell.
  \item \textbf{macOS.} Нажмите \cmd{Command} и пробел, введите
    «Терминал» (Terminal) в строке поиска и нажмите \cmd{Enter}.
  \item \textbf{Linux.} Откройте меню приложений и найдите «Терминал»
    (Terminal). В Ubuntu его также можно открыть сочетанием \cmd{Ctrl+Alt+T}.
\end{itemize}

Программу, с помощью которой вы подключаетесь к серверу по SSH, называют
\textbf{SSH-клиентом}. В терминале проверьте, доступен ли клиент OpenSSH:
\begin{minted}[bgcolor=gray!6]{bash}
ssh -V
\end{minted}
Параметр \cmd{-V} (заглавная латинская буква) выводит название и версию
программы. Если в ответ вы видите \cmd{OpenSSH} с номером версии, можно
подключаться. Если Windows не находит команду, найдите через меню «Пуск»
раздел «Дополнительные компоненты». Выберите добавление компонента,
найдите «Клиент OpenSSH» и установите его. Откройте PowerShell заново
и повторите проверку. Если установка требует прав администратора на
учебном компьютере, обратитесь к семинаристу.
В Windows также можно подключиться через PuTTY (раздел~\ref{sec:putty-login}).

\section{Первый вход на учебную ВМ}
\label{sec:first-ssh-login}

Чтобы начать подключение, выберите один из двух способов ниже.
В примерах имя пользователя --- \cmd{student17}, адрес сервера ---
\fpath{pglab.nsu.ru}. Подставьте данные, которые вы получили от
семинариста. Если вам предоставили вход только по ключу, сначала
подготовьте свой ключ по инструкции в разделе~\ref{sec:ssh-keys}.

\subsection{Подключение из терминала}

В терминале на своём компьютере введите команду. Слева от знака
\cmd{@} укажите имя пользователя на ВМ, справа --- адрес сервера.
\begin{minted}[bgcolor=gray!6]{bash}
ssh student17@pglab.nsu.ru
\end{minted}
Так подключаются к порту~22. Если вам выдали другой порт, используйте
вариант с параметром \cmd{-p}. Здесь и далее \cmd{2222} обозначает
порт для примера.
\begin{minted}[bgcolor=gray!6]{bash}
ssh -p 2222 student17@pglab.nsu.ru
\end{minted}
Если вместо запроса на вход появилось сообщение \emph{Connection timed out}
или \emph{No route to host}, проверьте адрес сервера и подключение к сети
НГУ. При сообщении \emph{Connection refused} сверьте номер порта с выданным
семинаристом.

При первом входе перейдите к проверке сервера (раздел~\ref{sec:host-key}).

\subsection{Подключение через PuTTY в Windows}
\label{sec:putty-login}

Откройте меню «Пуск», найдите PuTTY и запустите программу.
В окне \emph{Session} выберите тип подключения \emph{SSH}.
В поле \emph{Host Name (or IP address)} введите адрес
\fpath{pglab.nsu.ru}. В поле \emph{Port} оставьте 22 или укажите номер,
выданный семинаристом. Нажмите \emph{Open}. При первом подключении
PuTTY откроет окно проверки ключа сервера.

\subsection{Проверка сервера и ввод пароля}
\label{sec:host-key}

Перед вводом пароля убедитесь, что отвечает именно учебный сервер.
Если соединение установлено с чужим сервером, его владелец может получить
введённый вами пароль. При первом подключении SSH-клиент показывает
отпечаток ключа ответившего сервера для сверки с данными семинариста.
В терминале найдите строку с надписью \emph{key fingerprint}, в PuTTY ---
строку под надписью \emph{key fingerprint is}. Пример запроса в терминале
с отпечатком учебного ключа:
\begin{minted}[bgcolor=gray!6,fontsize=\footnotesize]{text}
ED25519 key fingerprint is SHA256:Mhrz34uPr0KgjPZE56WMYa62+EoUzf8D0yCZbFJfEL0.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
\end{minted}

Сверьте весь отпечаток, начиная с \cmd{SHA256:}, со значением,
полученным от семинариста. Точка в конце сообщения в отпечаток не
входит. Все символы должны совпасть, включая регистр букв. При совпадении введите
\cmd{yes} и нажмите \cmd{Enter} или нажмите \emph{Accept} в PuTTY.
Программа запомнит ключ сервера для следующих подключений.
Если значения различаются или у вас нет отпечатка для сверки, отмените
подключение и уточните отпечаток у семинариста.

В PuTTY после проверки появится запрос \cmd{login as:}. Введите имя
пользователя и нажмите \cmd{Enter}. При подключении командой \cmd{ssh}
имя уже указано в команде. Если для вашей учётной записи выдан пароль,
дождитесь запроса, например:
\begin{minted}[bgcolor=gray!6]{text}
student17@pglab.nsu.ru's password:
\end{minted}
Введите выданный пароль и нажмите \cmd{Enter}. При вводе пароля на
экране не появляются символы, в том числе звёздочки. Если в ответ на ввод
пароля появилось \emph{Permission denied}, проверьте имя пользователя
и раскладку клавиатуры. После успешного
входа вы увидите приглашение оболочки на ВМ, например:
\begin{minted}[bgcolor=gray!6]{text}
student17@lab:~$
\end{minted}

\section{Проверка подключения и выход}
\label{sec:verify-env}

Пока соединение открыто, команды в этом окне выполняются на учебной ВМ.
Проверьте, под каким именем вы вошли:
\begin{minted}[bgcolor=gray!6]{bash}
whoami
\end{minted}
В ответ должно появиться выданное вам имя пользователя. Например:
\begin{minted}[bgcolor=gray!6]{text}
student17
\end{minted}

Узнайте имя машины, на которой сейчас выполняются команды:
\begin{minted}[bgcolor=gray!6]{bash}
hostname
\end{minted}
Пример имени, заданного в Ubuntu на ВМ:
\begin{minted}[bgcolor=gray!6]{text}
lab
\end{minted}
Это имя может отличаться от адреса, который вы вводили для подключения.
Если семинарист сообщил имя вашей ВМ, сравните его с выводом команды.

Проверьте, в каком каталоге вы находитесь:
\begin{minted}[bgcolor=gray!6]{bash}
pwd
\end{minted}
При входе в систему текущим каталогом обычно становится домашний каталог
пользователя. Например, для пользователя \cmd{student17} команда выведет:
\begin{minted}[bgcolor=gray!6]{text}
/home/student17
\end{minted}

Когда закончите работу, сохраните открытые файлы. В приглашении
оболочки на ВМ введите:
\begin{minted}[bgcolor=gray!6]{bash}
exit
\end{minted}
Если вы подключались из терминала, снова появится приглашение вашего
компьютера. Если вы использовали PuTTY, окно соединения обычно
закроется. Сохранённые файлы останутся на ВМ. Чтобы продолжить работу
с ними, подключитесь к той же ВМ под тем же именем.

\section{Повторный вход по ключу}
\label{sec:ssh-keys}

Ключ сервера, который вы проверяли при подключении, позволяет узнать
сервер. Для входа под вашим именем можно использовать собственную
\textbf{пару ключей}. Это два связанных файла. \textbf{Открытый ключ}
можно передать семинаристу и добавить на ВМ в список ключей, которым
разрешён вход под вашим именем. \textbf{Закрытый ключ} остаётся на вашем
компьютере. Никому не отправляйте этот файл и не помещайте его в общую
папку с учебными работами.

\subsection{Создание ключей на своём компьютере}

Далее используются программы OpenSSH. Если вы работали в PuTTY,
для этих шагов откройте PowerShell с доступной командой \cmd{ssh}.
В macOS или Linux откройте терминал. Если вы ещё подключены к ВМ,
сначала завершите соединение как в разделе~\ref{sec:verify-env}.

Введите команду создания пары ключей. Параметр \cmd{-t} указывает тип
ключа, в примере выбран \cmd{ed25519}.
\begin{minted}[bgcolor=gray!6]{bash}
ssh-keygen -t ed25519
\end{minted}
\begin{enumerate}
  \item В ответ на \emph{Enter file in which to save the key}
    нажмите \cmd{Enter}, чтобы сохранить файлы под предложенным именем.
    Если появится вопрос \emph{Overwrite (y/n)?}, такой ключ уже есть.
    Введите \cmd{n} и нажмите \cmd{Enter}, чтобы сохранить существующую
    пару. Для следующих шагов можно использовать её открытый ключ.
  \item При создании новой пары на запрос \emph{Enter passphrase}
    придумайте и введите пароль. На следующий запрос повторите
    его. Пароль защищает файл закрытого ключа на вашем компьютере.
    Сохраните его в менеджере паролей. Восстановить пароль не получится. 
    Для дальнейшего входа по ключу потребуется создать новую
    пару и добавить её открытый ключ на ВМ.
\end{enumerate}

Программа сообщит, где сохранены файлы. При предложенном имени они
находятся в каталоге \fpath{.ssh} в вашей домашней папке.
Файл \fpath{id_ed25519.pub} содержит открытый ключ, а
\fpath{id_ed25519} --- закрытый. В примерах ниже знак
\cmd{~} обозначает домашний каталог. Чтобы найти открытый ключ в Windows,
введите \verb|%USERPROFILE%\.ssh| в адресной строке Проводника и нажмите
\cmd{Enter}. Если расширения скрыты, включите показ расширений имён файлов
в меню «Вид». В macOS откройте Finder, нажмите \cmd{Command+Shift+G}
и введите \fpath{~/.ssh}. В Ubuntu откройте приложение «Файлы», нажмите
\cmd{Ctrl+L} и введите тот же путь. В обоих случаях нажмите \cmd{Enter}.

\subsection{Добавление открытого ключа и проверка входа}

Если первый вход разрешён только по ключу, передайте семинаристу
файл \fpath{id_ed25519.pub}. Когда семинарист добавит ключ на ВМ,
переходите к проверке входа ниже.

Если вы уже входили по паролю и на вашем компьютере доступна команда
\cmd{ssh-copy-id}, добавьте открытый ключ самостоятельно. В локальном
терминале выполните:
\begin{minted}[bgcolor=gray!6]{bash}
ssh-copy-id -i ~/.ssh/id_ed25519.pub student17@pglab.nsu.ru
\end{minted}
Параметр \cmd{-i} указывает, какой открытый ключ скопировать. Для другого
порта добавьте, например, \cmd{-p 2222} перед именем пользователя.
По запросу введите пароль от ВМ. Программа добавит открытый ключ
в список разрешённых для вашей учётной записи.

Если команды \cmd{ssh-copy-id} нет (например, в PowerShell), тот же ключ
можно добавить вручную:
\begin{enumerate}
  \item На своём компьютере откройте файл \fpath{id_ed25519.pub}
    текстовым редактором (в Windows подойдёт «Блокнот»).
    Скопируйте всю строку, начиная с \cmd{ssh-ed25519}.
  \item Войдите на ВМ по паролю, как в разделе~\ref{sec:first-ssh-login}.
    Подготовьте на ВМ каталог для ключей. Следующая команда создаёт
    каталог, если он отсутствует, и оставляет доступ только его владельцу:
\begin{minted}[bgcolor=gray!6]{bash}
install -d -m 700 ~/.ssh
\end{minted}
  \item На ВМ откройте список разрешённых ключей в редакторе:
\begin{minted}[bgcolor=gray!6]{bash}
nano ~/.ssh/authorized_keys
\end{minted}
    Если файл пуст, вставьте скопированную строку в его начало. Если
    в нём уже есть ключи, добавьте её с новой строки после них.
    Для вставки воспользуйтесь командой «Вставить» в меню терминала
    (в PuTTY нажмите правую кнопку мыши внутри окна).
    Нажмите \cmd{Ctrl+O}, затем \cmd{Enter}, чтобы сохранить файл.
    Нажмите \cmd{Ctrl+X}, чтобы вернуться к приглашению оболочки.
\end{enumerate}

Для проверки откройте новое окно терминала на своём компьютере. Команда
ниже разрешает вход только по ключу. Если сервер не примет ключ, вы
увидите сообщение \emph{Permission denied (publickey)}. В этом случае
проверьте, что в учётную запись на ВМ добавлен ваш открытый ключ.
Для другого порта добавьте \cmd{-p} и его
номер перед именем пользователя.
\begin{minted}[bgcolor=gray!6]{bash}
ssh -o PreferredAuthentications=publickey student17@pglab.nsu.ru
\end{minted}
При первом подключении из этой программы сверьте отпечаток сервера,
как в разделе~\ref{sec:host-key}. Запрос \emph{Enter passphrase for key}
относится к парольной фразе вашего закрытого ключа. Появление
приглашения оболочки ВМ подтверждает, что вход по ключу выполнен.
Завершите это соединение командой:
\begin{minted}[bgcolor=gray!6]{bash}
exit
\end{minted}

\subsection{Короткое имя для подключения}
\label{sec:ssh-short-name}

Чтобы при каждом входе не вводить адрес, имя пользователя и порт,
их можно сохранить в файле настроек OpenSSH на своём компьютере.
В каталоге \fpath{.ssh}, где вы создали ключи, откройте текстовым
редактором файл \fpath{config}. Если файла ещё нет, создайте его
под именем \fpath{config} без расширения. Добавьте в конец файла:
\begin{minted}[bgcolor=gray!6]{text}
Host myvm
    HostName pglab.nsu.ru
    User student17
    Port 22
    IdentityFile ~/.ssh/id_ed25519
\end{minted}
После \cmd{Host} стоит короткое имя, которое вы выбираете сами.
В строку \cmd{HostName} впишите адрес сервера, в \cmd{User} --- имя
пользователя на ВМ, в \cmd{Port} --- выданный номер порта.
\cmd{IdentityFile} указывает путь к закрытому ключу на вашем компьютере.
Сохраните файл. Теперь для входа из локального терминала достаточно команды:
\begin{minted}[bgcolor=gray!6]{bash}
ssh myvm
\end{minted}

\subsection{Если при повторном входе изменился ключ сервера}

Предупреждение \emph{REMOTE HOST IDENTIFICATION HAS CHANGED!} означает,
что ключ отличается от сохранённого при предыдущем подключении.
Такое возможно после переустановки ВМ, но по одному сообщению причину
определить нельзя. Прервите подключение и уточните у семинариста,
менялся ли ключ. При подтверждённой замене получите новый отпечаток.

После подтверждения удалите в OpenSSH устаревшую запись для этого адреса
на своём компьютере. Для порта~22 выполните:
\begin{minted}[bgcolor=gray!6]{bash}
ssh-keygen -R pglab.nsu.ru
\end{minted}
Для другого порта укажите адрес в квадратных скобках и выданный номер:
\begin{minted}[bgcolor=gray!6]{bash}
ssh-keygen -R "[pglab.nsu.ru]:2222"
\end{minted}
Подключитесь заново и сверьте отпечаток, как при первом входе.
В PuTTY новый отпечаток можно сверить в самом окне предупреждения.
Подтверждайте замену только при совпадении с данными семинариста.

\section{Как запустить Linux на своём компьютере}
\label{sec:local-linux}

Если вы хотите выполнять задания на своём компьютере, а на нём установлен
Windows или macOS, способ установки зависит от того, как вы собираетесь
пользоваться Linux.

\textbf{Ubuntu в Windows.} Подсистема Windows для Linux (WSL) позволяет
открыть терминал Ubuntu и выполнять в нём команды Linux, продолжая
пользоваться приложениями Windows. В Windows~11 и Windows~10 версии 2004
или новее найдите PowerShell в меню «Пуск». Выберите «Запуск от имени
администратора» и выполните:
\begin{minted}[bgcolor=gray!6]{powershell}
wsl --install -d Ubuntu
\end{minted}
После установки перезагрузите компьютер и откройте Ubuntu из меню «Пуск».
При первом запуске придумайте имя пользователя и пароль для Ubuntu.
Когда появится приглашение оболочки, выполните команды из
раздела~\ref{sec:first-steps-terminal}.
\href{https://learn.microsoft.com/ru-ru/windows/wsl/install}{Инструкция по установке WSL.}

\textbf{Виртуальная машина на личном компьютере.} Этот вариант подходит,
если вы хотите работать с рабочим столом Ubuntu в отдельном окне.
Для этого используют, например, VirtualBox в Windows или UTM в macOS.
В программе создают ВМ, выделяют ей часть памяти и места на диске
компьютера и устанавливают в неё Ubuntu. Файлы такой ВМ хранятся на
вашем компьютере. Для работы с ними можно запустить ВМ без подключения
к сети НГУ.

\textbf{Linux как вторая операционная система.} Этот вариант подходит,
если вы хотите использовать Linux для повседневной работы. При включении
компьютера вы выбираете одну из двух установленных систем. Чтобы
перейти в другую, потребуется перезагрузка. Установка второй системы
меняет распределение места на диске. Перед установкой сохраните копии
важных файлов на другом носителе.
